# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a user-toggleable dark theme (navbar sun/moon toggle) across the entire site — customer pages and admin dashboard — using Tailwind's class-based `dark:` variant.

**Architecture:** A `ThemeProvider` client component toggles a `dark` class on `<html>` and persists the choice to `localStorage`; an inline blocking script in `<head>` applies the class before hydration to avoid a light-mode flash. Every component that currently hardcodes light-only Tailwind classes (`bg-white`, `text-zinc-900`, etc.) gets a paired `dark:` class alongside it — no new colors invented, the existing `zinc` scale is mirrored.

**Tech Stack:** Next.js 16 (App Router), React 19, Tailwind CSS v4, lucide-react icons.

**Spec:** `docs/superpowers/specs/2026-08-17-dark-mode-design.md`

## Global Constraints

- Tailwind v4 default `dark:` is media-query only — this project needs `@custom-variant dark (&:where(.dark, .dark *));` in `app/globals.css` for class-based toggling (per spec Architecture section).
- Accent `#E60012` (Suzuki red) never changes between themes — do not add `dark:` variants to any `#E60012`/`bg-[#E60012]`/`text-[#E60012]`/`border-[#E60012]` class.
- **Class-pairing table** (apply verbatim everywhere below — this is the single source of truth for every task in this plan):

| Light class | Add this dark: pair |
|---|---|
| `bg-white` | `dark:bg-zinc-900` |
| `bg-zinc-50` | `dark:bg-zinc-950` |
| `bg-zinc-100` | `dark:bg-zinc-800` |
| `bg-zinc-200` (skeleton/fill only) | `dark:bg-zinc-700` |
| `text-zinc-900` | `dark:text-zinc-100` |
| `text-zinc-700` | `dark:text-zinc-300` |
| `text-zinc-600` | `dark:text-zinc-400` |
| `text-zinc-500` | `dark:text-zinc-400` |
| `text-zinc-400` | `dark:text-zinc-500` |
| `text-zinc-300` (icon) | `dark:text-zinc-600` |
| `border-zinc-200` | `dark:border-zinc-800` |
| `border-zinc-100` | `dark:border-zinc-800` |
| `border-zinc-300` | `dark:border-zinc-700` |
| `divide-zinc-200` | `dark:divide-zinc-800` |
| `divide-zinc-100` | `dark:divide-zinc-800` |
| `ring-offset-white` | `dark:ring-offset-zinc-900` |
| `hover:bg-zinc-50` | `dark:hover:bg-zinc-800` |
| `hover:bg-zinc-100` | `dark:hover:bg-zinc-800` |
| `hover:bg-zinc-200` | `dark:hover:bg-zinc-700` |
| `hover:border-zinc-300` | `dark:hover:border-zinc-600` |
| `focus-visible:ring-zinc-950` | `dark:focus-visible:ring-zinc-100` |

- **Inversion exception:** any element whose *light* background is already `bg-zinc-900`/`text-white` (i.e., it's a dark-on-light accent element, like the default Button variant or default Badge variant) must **invert** in dark mode instead of mirroring, or it disappears against the dark page background. These are called out explicitly in Task 2 — don't apply the mirror table to them.
- Never remove or replace an existing light-mode class — only add the paired `dark:` class alongside it.
- Files already theme-safe (verified during planning, no changes needed): `components/Footer.tsx` (already `bg-zinc-900 text-white`), `components/HeroSection.tsx` (image overlay, already `text-white`), `app/(site)/scooters/page.tsx` (renders `VehicleCatalogPage`, covered by Task 5), `components/AddEditModal.tsx` (no hardcoded light classes found).

- [ ] **Step 4: Create ThemeProvider.tsx**

Create `components/ThemeProvider.tsx`:

```tsx
'use client'

import { createContext, useContext, useEffect, useState, type ReactNode } from 'react'

type Theme = 'light' | 'dark'

interface ThemeContextValue {
  theme: Theme
  toggle: () => void
}

const ThemeContext = createContext<ThemeContextValue | null>(null)

function applyTheme(theme: Theme) {
  document.documentElement.classList.toggle('dark', theme === 'dark')
}

export function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<Theme>('light')

  useEffect(() => {
    const stored = localStorage.getItem('theme') as Theme | null
    const initial = stored ?? (window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light')
    setTheme(initial)
    applyTheme(initial)
  }, [])

  const toggle = () => {
    setTheme((prev) => {
      const next = prev === 'dark' ? 'light' : 'dark'
      localStorage.setItem('theme', next)
      applyTheme(next)
      return next
    })
  }

  return <ThemeContext.Provider value={{ theme, toggle }}>{children}</ThemeContext.Provider>
}

export function useTheme(): ThemeContextValue {
  const ctx = useContext(ThemeContext)
  if (!ctx) throw new Error('useTheme must be used within a ThemeProvider')
  return ctx
}
```
